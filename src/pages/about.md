I'm a technical writer working on developer documentation for distributed
systems — peer-to-peer networking, storage, and blockchain products. Most of my
work starts in a source repository and ends in a procedure someone can follow
without asking a follow-up question.

## What I write

- **Procedures** — task-based documents with numbered steps and per-step
  verification. Two are in the [writing samples](/docs/).
- **Tutorials** — learning-oriented walkthroughs that build one working thing.
- **References** — exhaustive, lookup-oriented descriptions of a CLI, format, or
  API.

## How I work

- Source repositories, PRs, and RFCs are the primary evidence. I read the code
  before I describe it.
- Every command in a document is one I have run.
- Each document type has a template that fixes section order and content rules,
  so a reader who has read one procedure can navigate the next one immediately.
- Second person, no marketing language, no filler adjectives.
